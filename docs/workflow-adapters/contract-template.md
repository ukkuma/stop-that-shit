# Task completion contract｜可选模板

> 这是**任务级**模板，不是另一套全局 Authority，也不是供每次自动填充的表格。只有复杂、多阶段或涉及重要来源／写入风险时，才取用必要字段。项目已有明确合同就直接使用原合同。

## Minimal contract

```text
RESULT: 本次承诺交付的具体结果
MODE: review / answer / monitor / change / watch
AUTHORITY: 当前用户指令与已批准项目规则
SCOPE: 涉及对象、项目阶段、已冻结集合、明确禁止范围
SOURCE: 本次必须读取的真实原始来源及版本
REQUIRED_CHECKS: 哪些检查不可跳过；何种证据算有效
ALLOWED_WRITES: 已明确授权的写入位置与必要联动
CHECKPOINT: 中间进度；不自动代表整个任务完成
STOP: 完整交付且验收通过；或记录了真实且未解决的阻塞
EVIDENCE: 真实读取／验证的回执；不得声称未发生的工作已完成
```

## Evaluation rules

- **复用现有证据**：必须匹配同一来源、同一修改后状态与同一验收口径；内容变了就重新核验受影响部分。
- **有证据的保护照做**：完整性核验、溯源、并发保护、授权、安全、兼容性或可访问性即使增加工作量，也不可省略。
- **写入之前**：获取最新目标，确认版本与并发；对更新范围进行最小必要修改，不覆盖其他作者新内容。
- **局部完成之后**：如果当前请求明确要求继续下一批，不因为阶段性 PASS 就结束；如果本轮只授权一批，也不擅自扩展下一批。
- **阻塞时**：保留真实完成部分，说明剩余内容与未验证之处；不用摘要冒充全文，也不写虚假 PASS。
- **权限冲突**：明确 Scope 与真实必要联动冲突时先报告，不在隐含“必要”名义下突破明确的文件／写入禁令。

## Optional STS directive examples

以下仅为支持该插件的宿主提供参考；是否真正拦截须通过宿主验证。

```text
$stop-that-shit watch -- 观察本批任务的必要和多余动作，不改变当前授权。
$stop-that-shit review -- 只读审查指定差异，不修改文件。
$stop-that-shit change hash=allow -- 按项目已批准合同执行完整性校验与必要修改。
```

只有完整修改路径已经核实，才使用 `lock change files=...`；不要凭猜测设置文件锁而导致必需联动无法完成。
