# Workflow Bad / Good scenarios

> 概念性案例，非真实运行记录；这里只描述**应该怎样判断**，没有声称现有 Guard 会自动理解这些领域的完整语义。测试宿主适配与实际阻断必须另做。

| 决定性事实 | Bad（应停止） | Good（应继续） | 为什么 |
| --- | --- | --- | --- |
| 用户要求只读评估一个文档 | 找到问题就改写全部正文 | 只报告可复现的缺陷及精确位置 | 审查权限不是修改权限 |
| 同一天多人编辑日页 | 用昨日缓存全文覆写最新内容 | 重新读取最新目标、发现并发改动、最小范围插入并验证 | 必须保护其他作者新写的内容 |
| 批处理已完成第3/10批且要求连续推进 | 第3批 PASS 后宣布总任务完成 | 保存本批证据后继续第4批；确有阻塞则如实说明 | 中间Checkpoint不等于全局停止条件 |
| 第3批证据仍有效且源文未变 | 无理由重做这批所有项目 | 复用已核验结果，审查新增范围 | 重复计算不增加可信度 |
| 来源文字未读取到全文 | 用搜索摘要／粗读概括冒充全文深审 | 补足完整原文与必要评论，或记为未验证 | 节省 token 不允许伪造证据 |
| 发布工作流明确读取SHA以拒收损坏文件 | 禁止生成任何hash | 做批准的hash与原始字节比对，必要时显式 `hash=allow` | 真实消费者与拒收行为使保护必要 |
| 一个新脚本输出无人消费的额外hash文件 | 为“以后可能要”自动生成旁支校验流程 | 只保留本次交付要求的输出 | 无当前用途的额外复杂度应停 |
| 用户仅交付一本书的Markdown并要求评估是否值得学习 | 自动创建全套课程、练习和知识Current | 先检查来源与学习价值，等真实学习指令再进入一个Learning Block | 发现、学习、掌握与晋升不同 |
| 用户要求按章节教学并实际验证理解 | 为减少步骤跳过解释、练习和反馈 | 按当前Learning Block教学并根据真实理解补充必要例子 | 完成学习责任比最小调用次数重要 |
| 只要求给一个平台的发布稿 | 同时批量制造多平台版本 | 交付指定平台版本、保留事实和作者口吻 | 没有授权的版本扩张是范围膨胀 |
| 原句有真实不确定性 | STSS把“可能”删成“必然” | 精简堆叠修饰但保留关键概率／条件 | 可读性不允许改变证据强度 |

## What to verify in a future pilot

1. **Bad Case**：未授权写入、扩大范围、多余hash、重复委派／复查是否被识别。
2. **Good Case**：必须的SHA、历史数据兼容、来源完整性、必要调用方与Checkpoint续办是否保持可执行。
3. **Mode Integrity**：只读／允许修改模式与项目合同一致；没有用引用中的文本错误切换模式。
4. **Host Evidence**：区分插件决定、工具返回值、实际文件状态；不能把插件的deny响应直接当作系统级隔离证据。

先用模拟任务和公开数据，不拿私人档案做试验。
