# Workflow adapters｜为多类工作流使用 STS

> Fork-local、可选的适配说明；**不是上游项目的正式契约、已安装的 Hook、自动执行权限或新的 Workflow 引擎**。本目录没有修改 `src/`、`hooks/`、`skills/` 或发布包。使用前先读 [STS Skill](../../skills/stop-that-shit/SKILL.md)、[Host Adapter Contract](../../HOST-ADAPTER-CONTRACT.md) 与 [STSS Skill](../../skills/stss/SKILL.md)。

## 目标与责任边界

**把明确交付做完整，停止没有必要的额外动作。** 先分清三个层次：

- **业务 Workflow / 项目契约**：任务范围、真实来源、允许修改对象、必需验证、Checkpoint、完成条件及异常处置由该项目的现行规则决定。
- **STS Skill**：在考虑新增工作、验证或防御时，提供判断；不自动授予写权限，不替代宿主的沙箱与并发控制。
- **STS Guard**：只对受支持宿主及被识别的动作生效。仅安装 Skill 或处于 `watch` / `unconfirmed` 时，不能声称写入被禁止。观察到 Guard 返回 deny，也不能据此声称宿主最终没有执行操作。

**判定顺序**：用户本轮明确指令及已批准的项目验收要求 → 项目范围与现行 Workflow → STS 可选建议／启用时的显式 Guard 合同。规则冲突时不要静默扩大权限；也不要用“减少工作”删除必需的 QA。

## 六类使用场景

| 场景 | STS 建议 | 核心保留项 | 常见的多余动作 |
| --- | --- | --- | --- |
| 代码修复、局部脚本维护 | 在支持的宿主中从 `watch` 开始，按需采用 `review` 或 `change` | 必要调用方、迁移、测试、已批准文件边界 | 未相关重构、额外依赖、无新证据的复查 |
| 多阶段批处理／归档 | 优先采用 Skill 的范围与验收判断；仅在宿主兼容且合同明确时启用 Guard | 冻结队列、逐项覆盖、有效 Checkpoint、校验和、可追溯证据 | 对已审且证据未失效的记录重复首审、擅自添加新成果 |
| 多人协作文档更新 | 采用 Scope 与 Intent 规则，不把 Guard 视为版本锁 | 写前新鲜读取、并发检测、限定差异、写后回读 | 用旧全文覆盖最新文件、修改无关排版 |
| 来源采集、转换、目录同步 | 采用 Stop Ladder 并保持来源链 | 原始来源完整性、去重需要的哈希、编号／元数据一致性 | 自行扩展到整站抓取、反复生成相同转换物 |
| 对话式教学、资料学习 | 仅轻量使用聚焦原则；不要默认安装强制 Guard | 解释、练习、反馈、学习证据、合理延伸与回到主线 | 将新分支自动变成完整课程、自动创建一串笔记 |
| 文章、发布文案、提案 | 可选用 [STSS](../../skills/stss/SKILL.md) 收紧赘述 | 事实、归属、有效限制、作者风格、必要发布版本 | 多平台版本无授权批量生成、冗余自我辩护 |

探索性创作、商业研究和开放讨论**不应因发散本身被判为 SHIT**。只限制用户没有授权的执行副作用；概念探索与正式修改要分开。

## 三个必保留的判断

### 1. Checkpoint 不等于完成

单个批次通过 QA，只能证明该批完成。若当前任务要求继续处理下一批，且资源、权限和来源条件允许，应继续推进。**整个任务结束**只有当请求的交付和所有明确必需的验收全部成立，或真实阻塞已如实报告时才成立。

### 2. 有消费者的验证不是浪费

在当前 Workflow 中，哈希、逐字节回读、可复现来源检查或回归测试可能是受信任的交付条件。若 Guard 会阻止明确授权的 SHA 操作，在支持此选项的宿主中以显式 `hash=allow` 设置合同；这不免除判断是否真的需要验证，也不绕过项目授权。

### 3. 最小修改不等于不完成必要联动

优先最小可行差异，但若完成任务必须一起修改调用方、引用链接、配套测试或迁移，不能为了“小 diff”遗漏。反过来，非必须的目录美化、文件重命名和历史重写不自动获权。

## 建议的接入方式

1. **先只读比对**当前 Workflow 的 Scope、Stop Conditions、QA 是否已有类似规则。已有且执行有效时，不再添加一份同义文档。
2. 发现真实缺口时，借用 [契约模板](contract-template.md) 中相关字段，放回**原 Workflow 的唯一 Current**或当前任务指令；不以本目录的新文件替代其权威。
3. 用 [正反例](scenarios.md) 判断“多做／少做”的决定性事实，并记录 **Bad 和 Good**，特别是强制 Guard 可能误拦截的必要验证。
4. 仅对适合的编程宿主，在代码审查与 Hook 信任检查后，从 `watch` 观察；任何强制模式先限定单个任务，不做无差别全局启用。
5. 修改后验证与交付；没有新阻塞时不要自发增加一轮审计。

### 隐私与维护

这个 Fork 是公开仓库。本目录**只放通用示例**，不要提交私人 Vault 路径、真实用户对话、客户资料、隐私信息、内部来源 ID 或仓库中的私密任务契约。个人或组织项目的具体映射保存在其已有受控工作区。上游升级时先比较差异，避免改写原版的 Guard / Skill 语义。

**当前状态：文档适配草案；没有 Hook 安装、宿主执行验证或针对任何具体私有 Workflow 的自动部署。**
